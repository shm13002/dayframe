# 11 — Decisions and Rejections Log

| ID | Decision | Alternatives Considered | Rationale |
|---|---|---|---|
| `DEC-V13-001` | Route `"Resume <project>?"` through `BriefingNotice.Kind.resume` with a 3-second fallback to the existing AppleScript dialog. | (A) Keep the gray AppleScript dialog; (B) Remove the AppleScript fallback entirely. | (A) leaves jarring UI inconsistency right after the notch briefing peek; (B) would drop the resume prompt when Dayframe is closed or the Notch Island is disabled. The 3-second `.ack` hand-off gives native notch UX when Dayframe is running and 100% reliability when closed. |
| `DEC-V13-002` | Preempt passive unread `.brief` notices when `.ask`, `.resume`, or `.peek` notices arrive, re-queuing the `.brief` behind them. | (A) FIFO queue for all notices; (B) Drop the unread `.brief` notice when `.ask`/`.resume` arrives. | (A) starves `.ask` and `.resume` for 3 hours (`FIND-V13-002`); (B) loses the unread briefing indicator on Jarvis's eyes. Preempting and re-queuing preserves both immediate interactivity and the unread briefing card. |
| `DEC-V13-003` | Extend `Briefing/improve.py` in-place into the bounded Evolution Engine rather than introducing a separate daemon or multi-agent service. | (A) Separate multi-agent Python/Node daemon; (B) In-place evolution of `Briefing/improve.py` and `dashboard.html`. | `Briefing/improve.py` already owns git worktree isolation, AST safety rails (`PROTECTED_FUNCS`), memory-hash checks, and LaunchAgent scheduling. Extending it in-place keeps zero extra background processes and 100% backward compatibility with existing tests. |
| `DEC-V13-004` | Deduplicate rejected proposals within the same execution mode (`is_duplicate_rejected(cand, mode)`). | (A) Never deduplicate; (B) Deduplicate globally across all modes even when the user switches to `controlled_autonomous`. | Deduplicating per-mode prevents nightly guided cycles from nagging the user with a proposal they already rejected, while still allowing an explicit switch to `controlled_autonomous` (`improve_auto_apply_params=True`) to apply parameter tuning (`test_reject_and_auto_apply`). |
